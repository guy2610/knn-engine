# ADR-0001: Use C++20

## Status

Accepted

## Context

The project is intended to be developed in modern, idiomatic C++ and will explore areas including algorithms, concurrency, systems programming, networking, and performance engineering.

The language version should provide useful modern facilities while remaining well supported by current GCC and Clang toolchains on Linux and macOS.

Using a newer standard can provide additional language and library features, but also increases toolchain requirements and may reduce portability.

## Options Considered

### C++17

Advantages:

* very broad compiler support
* mature ecosystem
* sufficient for most project requirements

Disadvantages:

* lacks several facilities that are useful for this project
* would require custom or third-party alternatives for some modern abstractions

### C++20

Advantages:

* strong support in modern GCC and Clang
* `std::span` for non-owning contiguous views
* `std::jthread` and `std::stop_token` for structured thread management and cancellation
* concepts for expressing meaningful template constraints
* ranges where they improve clarity
* broad ecosystem compatibility

Disadvantages:

* requires newer toolchains than C++17
* some C++20 library features may have uneven support on older systems

### C++23

Advantages:

* additional library and language improvements
* facilities such as `std::expected` can improve some APIs

Disadvantages:

* newer toolchain requirement
* support is less uniform across environments
* most currently planned functionality does not require C++23

## Decision

Use C++20 as the project language standard.

C++20 requirements should be expressed at the CMake target level using:

```cmake
target_compile_features(target PUBLIC cxx_std_20)
```

or the appropriate visibility for the target.

## Rationale

C++20 provides features that are directly relevant to the project's expected work, especially non-owning views, concurrency, and expressive generic programming.

It provides these capabilities without requiring the project to depend on the newest available language standard.

The choice also leaves room to introduce selected newer facilities later if a concrete requirement justifies increasing the minimum language version.

## Consequences

* CI must use compilers with reliable C++20 support.
* Code may use C++20 features when they improve design, correctness, or maintainability.
* Modern features should not be introduced only for novelty.
* The project should avoid accidental dependence on C++23 unless the language-version decision is revisited.

## Revisit Conditions

Reconsider this decision if:

* an important feature requires C++23
* maintaining C++20 compatibility creates significant unnecessary complexity
* the supported compiler environments make a newer standard effectively universal
